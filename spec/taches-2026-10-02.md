## Tâche 1 — Rendre visible le sol randomisé

### Objectif

Dans le viewer, on voit que le sol change d'un épisode à l'autre.

### À savoir avant de commencer

- **Le sol n'est pas accidenté.** Il reste plat. Ce qui est randomisé, c'est sa
  **friction** (glissant ou adhérent), tirée à chaque épisode. Il n'y a aucun relief
  dans le code.
- **Le viewer ne randomise rien.** `scripts/viewer.py` ouvre le fichier XML directement,
  sans passer par l'environnement. La randomisation n'a lieu que dans
  `PoppyHumanoidEnv`, et seulement avec `floor_noise=True`.

### Où regarder

| Fichier | Ce qu'il contient |
| --- | --- |
| `scripts/viewer.py` | Le viewer : charge le XML et ouvre la fenêtre. |
| `src/environments/poppy_humanoid_env.py`, `_randomize_floor` (l. 583) | Le tirage de la friction à chaque `reset()`. |
| `src/environments/poppy_humanoid_env.py`, `get_floor_randomization_info` (l. 601) | Renvoie la friction tirée. |
| `configs/poppy_robust.yaml`, l. 39 | La plage utilisée à l'entraînement : `[0.4, 2.0]`. |

### À faire

1. Faire tourner le viewer sur l'environnement (`PoppyHumanoidEnv(floor_noise=True)`)
   plutôt que sur le XML seul, pour que la friction soit tirée.
2. Donner au sol une apparence qui dépend de sa friction : couleur, brillance… au
   choix.
3. Pouvoir relancer un épisode pour voir le sol changer.

### Ne pas faire

- Changer la plage ou la façon de tirer la friction.
- Corriger la « restitution » écrite à la ligne 599 : c'est un défaut connu
  (`docs/TECHNIQUE.md` §8), qui change l'entraînement.

### Terminé quand

- [ ] Deux épisodes de suite montrent deux sols visiblement différents.
- [ ] `docker compose --profile dev run --rm dev python -m pytest` → `16 passed, 1 xfailed`.

## Tâche 2 — Rendre le viewer plus esthétique

### Objectif

Le viewer est agréable à regarder : Poppy en couleurs, sol en damier.

### Où regarder

Tout est dans `assets/poppy_humanoid/poppy_humanoid.xml` :

| Lignes | Contenu |
| --- | --- |
| 22-77 | `<asset>` : on y ajoute textures et matériaux. |
| 80 | La seule lumière. |
| 85-87 | Le sol, nommé `floor`. **Garder ce nom**, le code le cherche. |
| 97 et suivantes | Les pièces du robot. |

Chaque pièce a deux géométries :

- `mesh="..._v"` avec `contype="0" conaffinity="0"` : **celle qu'on voit**, à colorer.
- `mesh="..._c"` : celle des collisions. **Ne pas y toucher.**

Les moteurs ont leurs propres maillages (`*_motor_v`, `abs_motors_v`,
`bust_motors_v`), pour les colorer à part des pièces.

### À faire

1. Colorer les pièces du robot. Couleurs libres ; le vrai Poppy du club peut servir
   d'inspiration.
2. Mettre le sol en damier (texture `builtin="checker"`).
3. Optionnel : un ciel, un meilleur éclairage.

### Ne pas faire

- Toucher à la physique : masses, friction, `contype`, `conaffinity`, articulations,
  moteurs.

### À savoir

- Si une géométrie a un `rgba` **et** un `material`, c'est le `rgba` qui s'affiche.
  Retirer le `rgba` quand on met un matériau.
- Lecture utile : [référence XML MuJoCo](https://mujoco.readthedocs.io/en/stable/XMLreference.html),
  sections `texture`, `material`, `geom`.
- Exemple de sol en damier : [`humanoid.xml` de MuJoCo](https://github.com/google-deepmind/mujoco/blob/main/model/humanoid/humanoid.xml).

### Terminé quand

- [ ] Poppy est en couleurs, moteurs distincts des pièces.
- [ ] Le sol est en damier et s'appelle toujours `floor`.
- [ ] `docker compose --profile dev run --rm dev python -m pytest` → `16 passed, 1 xfailed`.
